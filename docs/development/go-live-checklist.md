# First server go-live checklist

Use this with [deploy.md](deploy.md) and [operations.md](operations.md). If the server already hosts other sites (CyberPanel, for example), install ViStud in its sealed Docker box instead of steps 1 and 3: see [docker-deploy.md](docker-deploy.md); the other steps still apply. Server installation, service configuration, backup jobs and mail delivery are **unverified** until Abel checks them on the server. Keep traffic closed and do not issue class links until the gate is open.

1. **Prepare Linux.** Install PHP 8.4.1+ FPM/CLI with `intl`, `openssl` (verify AES-256-GCM), `sodium`, `zip`, `gd`, `pdo_mysql` and `mbstring`; MySQL 8.4, nginx, Composer, Node, ffmpeg, LibreOffice and supervisor. Verify FPM and CLI extensions, executable paths, HTTPS and the configured upload limits. Mount private RAM-backed temps; set `VISTUD_TEMP_ROOT`, PHP FPM/CLI `upload_tmp_dir` and `sys_temp_dir`, process `TMPDIR`/`TMP`/`TEMP`, and nginx `client_body_temp_path` to restricted RAM paths. Check capacity, permissions, swap and cleanup as in operations.md.
2. **Provision secrets and independent erasure storage.** Privately provide `VISTUD_MASTER_KEY` to PHP-FPM, queue workers and scheduler/CLI process environments; never put it in cached config. Keep two verified encrypted offline recovery copies in separate locations. Set `VISTUD_ERASURE_LEDGER_PATH`, `VISTUD_ERASURE_LEDGER_ID` and independent `VISTUD_ERASURE_LEDGER_KEY` in those process environments; never cache the ledger key. The live ledger is on independently retained storage outside the checkout and backup sets; immutable exports and the latest authenticated checkpoint go to a separately controlled off-site copy. Initialise and verify it only as described in operations.md. Actual locations and durability are **unverified**.
3. **Configure delivery and processes.** Set a working mail transport (`MAIL_MAILER=smtp`, with the corresponding `MAIL_HOST`, `MAIL_PORT`, credentials, scheme and `MAIL_FROM_ADDRESS`, or another configured real transport). Send a class-link verification email to a controlled test inbox and complete the signed confirmation; log delivery alone is not proof. Mail delivery is **unverified**. Set `QUEUE_CONNECTION=database`; run and supervise/restart the queue worker and scheduler. Start the worker with `--memory=512` (Laravel's default of 128 MB ends the worker, exit code 12, after any job that grew past it; supervisor restarts it, but big file reads then restart it often). deploy.md specifies supervisor for `queue:work` and a minute cron for `schedule:run`; if using supervisor for the scheduler, verify `schedule:work` runs and restarts. Confirm job processing, scheduled tasks, bounded timeouts and hourly temp pruning. Server process setup is **unverified**.
4. **Schedule and verify backups.** Take separate, restorable daily data/source-file backups (35 days), key-database backups (7 days), binlogs (7 days), and operational logs (30 days); retain the independent erasure ledger indefinitely. Schedule removal of every pre-encryption backup 14 days after verified conversion. Test recovery and replay of the latest independent ledger before reopening any restored copy. Actual schedules and restore drill are **unverified**.
5. **Restore and convert while offline.** Take and verify matching backups; stop writers, queue workers and scheduler, and enter maintenance. Restore Abel's database dump and source files; preserve the required existing `APP_KEY`. **If the dump is from the already-converted local installation, restore its matching learner-key database and original master key as well; never provision replacement keys for encrypted data.** Follow deploy.md's **Learner keys** steps: prepare the separate key database, migrate keys and main schema with owner connections, dry-run and provision existing learners, and resolve all key errors. Run text backfill dry-run, conversion with `--backup-confirmed`, and unrestricted `--verify`; dry-run then clear the specified text caches. Run file backfill dry-run, reconcile stray/unmapped files against the backup (the first local setup found them), then convert and run unrestricted `--verify`. Run `vistud:encrypt:ai-keys --dry-run`, convert offline, and rerun the dry-run to confirm zero failures and conversions. Follow deploy.md and operations.md for all checks and recovery; do not roll back a live key database or reinitialise an existing ledger.
6. **Prove this release before admission.** On the exact commit being released, arrange isolated `vistud_test` and `vistud_keys_test` databases with suitable test-only credentials, an external temp path and the Composer dev dependencies including PHPUnit; deploy.md's `composer install --no-dev` alone cannot run acceptance. Run `php artisan vistud:gate:record-acceptance`, then `php artisan vistud:gate:second-learner`. Any subsequent commit makes the acceptance record stale. Abel must arrange human privacy-policy review and record it as required by the gate. Verify mail, queues, scheduler, restore safeguards, and a private smoke test; restart processes and reopen only after all checks succeed. The present privacy review and server validation are **unverified**.
